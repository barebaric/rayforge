# 命令

命令步骤将自定义机器代码注入作业中，注入位置正是该步骤在图层工作流程中所处的位置。使用它来发送几何操作无法涵盖的命令：定位机头、在特定操作前后开关空气辅助或其他设备，或发送特定机器的代码。

![命令步骤设置](/screenshots/step-settings-command-general.webp)

## 概述

命令步骤：

- 保存多行机器代码块，每行一条命令
- 作业编码时，在步骤所在位置逐行原样输出
- 每个图层运行一次，位于其工作流程位置——它不作用于工件
- 图层中没有任何工件也能工作，因此只包含命令步骤的图层仍然可以生成作业
- 支持与宏相同的路径变量（见下文）

文本以未展开的形式存储在项目中，因此会随 `.ryp` 文件一起保存，并准确记录了发送的内容及其去向。

## 何时使用命令步骤

将命令步骤用于：

- 预定位机头（例如在切割开始前抬起 Z 轴）
- 在操作之间开关空气辅助、冷却或其他设备
- 在作业前后发送特定控制器的代码
- 在两个操作之间用 dwell 短暂停顿

**不要将命令步骤用于：**

- 在图层或工件边界重复 G 代码——[宏和钩子](../../machine/hooks-macros.md)会自动触发，并且在非 G 代码机器上也有效
- 在计算机上运行程序（当前阶段不支持此功能）

## 添加命令步骤

1. 在右侧面板中打开图层的工作流程。
2. 点击**添加步骤**按钮并选择**命令**。
3. 在文本框中输入机器代码，每行一条命令。空行会被跳过。

该步骤可以放在其他步骤之前、之间或之后，并且可以在一个图层中多次使用。它在工作流程中的位置就是其各行在生成的机器代码中的位置。

## 路径变量

与宏一样，各行可以包含路径变量，这些变量在作业编码时被解析。未知变量保持不变，即使步骤在图层中间运行，`layer.*`
变量也会被解析。

| 变量               | 示例       | 描述                      |
| ------------------ | ---------- | ------------------------- |
| `{machine.name}`   | `My Laser` | 活动机器的名称            |
| `{layer.name}`     | `Layer 1`  | 正在处理的图层的名称      |
| `{job.extents[0]}` | `210.0`    | 作业在 X 轴上的尺寸（mm） |
| `{wcs_offset[0]}`  | `5.0`      | 活动工作坐标系的 X 偏移量 |

例如，类似 `; 正在切割 {layer.name}，机器 {machine.name}` 的注释在编码时会填入名称。

## 机器支持

命令步骤在每台机器上都可用，但只有使用机器代码的驱动程序才会输出这些行。当活动机器的驱动程序不支持时（例如 Ruida），步骤会显示警告，其各行不会包含在生成的输出中。
