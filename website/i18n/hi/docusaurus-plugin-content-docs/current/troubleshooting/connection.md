# कनेक्शन समस्याएँ

यह पृष्ठ आपको सीरियल कनेक्शन के माध्यम से Rayforge को अपने लेज़र मशीन से जोड़ने की समस्याओं के निदान
और समाधान में मदद करता है.

## त्वरित निदान

### लक्षण

सामान्य कनेक्शन समस्याओं में शामिल हैं:

- कनेक्ट करने की कोशिश करते समय "पोर्ट कॉन्फ़िगर किया जाना चाहिए" त्रुटि
- कनेक्शन बार-बार विफल होकर पुनः कनेक्ट होना
- पोर्ट सूची में सीरियल पोर्ट दिखाई न देना
- सीरियल पोर्ट खोलने की कोशिश करते समय "अनुमति अस्वीकृत" त्रुटियाँ
- डिवाइस कनेक्ट होता दिखता है लेकिन कमांडों का प्रतिक्रिया नहीं देता

---

## सामान्य समस्याएँ और समाधान

### कोई सीरियल पोर्ट पहचाना नहीं गया

**समस्या:** सीरियल पोर्ट ड्रॉपडाउन रिक्त है या आपका डिवाइस नहीं दिखाता.

**निदान:**

1. जाँचें कि आपका डिवाइस चालू और USB से जुड़ा है
2. USB केबल अनप्लग करके दोबारा प्लग करने का प्रयास करें
3. USB केबल किसी अन्य डिवाइस से परीक्षण करें (केबल विफल हो सकते हैं)
4. कंप्यूटर का भिन्न USB पोर्ट आज़माएँ

**समाधान:**

**Linux:**

पहले, अपने उपयोगकर्ता को `dialout` समूह में जोड़ें (अधिकांश Debian-आधारित वितरणों पर Snap और
गैर-Snap दोनों इंस्टॉलेशन के लिए आवश्यक):

```bash
sudo usermod -a -G dialout $USER
```

फिर बदलाव लागू होने के लिए लॉग आउट करके वापस लॉग इन करें.

यदि आप Snap संस्करण उपयोग कर रहे हैं, तो आपको सीरियल पोर्ट अनुमतियाँ भी प्रदान करनी होंगी:

```bash
sudo snap connect rayforge:serial-port
```

विस्तृत Linux सेटअप के लिए [Snap अनुमतियाँ](snap-permissions) देखें.

**Windows:**

1. Device Manager खोलें (Win+X, फिर Device Manager चुनें)
2. अपने डिवाइस के लिए "Ports (COM & LPT)" के अंतर्गत देखें
3. यदि पीला चेतावनी आइकन दिखे, तो ड्राइवर अपडेट या पुनः इंस्टॉल करें
4. COM पोर्ट नंबर नोट करें (जैसे, COM3)
5. यदि डिवाइस बिल्कुल सूचीबद्ध नहीं है, तो USB केबल या ड्राइवर दोषपूर्ण हो सकता है

**macOS:**

1. डिवाइस पहचाना गया है सत्यापित करने के लिए System Information → USB जाँचें
2. यदि आपका नियंत्रक यह चिपसेट उपयोग करता है तो CH340/CH341 ड्राइवर इंस्टॉल करें
3. `/dev/tty.usbserial*` या `/dev/cu.usbserial*` डिवाइसों की जाँच करें

### अनुमति अस्वीकृत त्रुटियाँ

**समस्या:** कनेक्ट करने की कोशिश करते समय आपको "अनुमति अस्वीकृत" या समान त्रुटियाँ मिलती हैं.

**Linux पर:**

आपके उपयोगकर्ता को `dialout` समूह में (कुछ वितरणों पर `uucp`) होना चाहिए. AppArmor DENIED संदेशों से
बचने के लिए Debian-आधारित वितरणों पर यह **Snap और गैर-Snap दोनों इंस्टॉलेशन** के लिए आवश्यक है:

```bash
# Add yourself to the dialout group
sudo usermod -a -G dialout $USER

# Verify you're in the group (after logging out/in)
groups | grep dialout
```

**महत्वपूर्ण:** समूह बदलाव लागू होने के लिए आपको लॉग आउट करके वापस लॉग इन करना होगा (या रीबूट करना
होगा).

**Snap इंस्टॉलेशन के लिए अतिरिक्त**, snap को सीरियल पोर्ट पहुँच प्रदान करें:

```bash
sudo snap connect rayforge:serial-port
```

अधिक जानकारी के लिए [Snap अनुमतियाँ](snap-permissions) गाइड देखें.

**Windows पर:**

सीरियल पोर्ट का उपयोग कर रहे किसी अन्य एप्लिकेशन को बंद करें (जिनमें शामिल हैं:

- Rayforge के पिछले इंस्टेंस
- सीरियल मॉनिटर उपकरण
- अन्य लेज़र सॉफ़्टवेयर
- Arduino IDE या समान उपकरण

### गलत सीरियल पोर्ट चयनित

**समस्या:** Rayforge कनेक्ट होता है लेकिन मशीन प्रतिक्रिया नहीं देती.

**निदान:**

आपने गलत पोर्ट चुना हो सकता है, विशेष रूप से यदि आपके पास कई USB डिवाइस जुड़े हैं.

**समाधान:**

1. सभी अन्य USB सीरियल डिवाइस डिस्कनेक्ट करें
2. नोट करें कि Rayforge में कौन से पोर्ट उपलब्ध हैं
3. अपना लेज़र नियंत्रक प्लग करें
4. पोर्ट सूची ताज़ा करें - नया पोर्ट आपका लेज़र है
5. Linux पर, लेज़र नियंत्रक प्रायः इनके रूप में दिखाई देते हैं:
   - `/dev/ttyUSB0` (CH340 चिपसेट के लिए सामान्य)
   - `/dev/ttyACM0` (नेटिव USB नियंत्रकों के लिए सामान्य)
6. Windows पर, Device Manager से COM पोर्ट नोट करें
7. Linux पर `/dev/ttyS*` नाम के पोर्ट टालें - ये हार्डवेयर सीरियल पोर्ट हैं, USB नहीं

<!-- prettier-ignore-start -->
:::tip[पुनः कनेक्ट के बाद मशीन पोर्ट बदल जाता है]
यदि रीबूट या पुनः कनेक्ट के बाद आपकी मशीन का पोर्ट बदल जाता है (जैसे
`/dev/ttyUSB0` से `/dev/ttyUSB1`), तो इसके बजाय इसे USB पहचान से बाँधें: पोर्ट पथ के बजाय
सीरियल पोर्ट फ़ील्ड में डिवाइस का VID:PID (जैसे `0403:6001`) दर्ज करें. स्वतः-पुनः कनेक्ट तब मशीन
का नए पोर्ट पर पालन करता है.
[सीरियल पोर्ट बाइंडिंग](../machine/general.md#serial-port-binding) देखें.
:::

क्योंकि ये प्रायः USB-आधारित GRBL डिवाइस नहीं होते. USB सीरियल पोर्ट `/dev/ttyUSB*` या
`/dev/ttyACM*` उपयोग करते हैं.
:::

### गलत बॉड दर

**समस्या:** कनेक्शन स्थापित होता है लेकिन कमांड काम नहीं करतीं या विकृत प्रतिक्रियाएँ देती हैं.

**समाधान:**

GRBL नियंत्रक प्रायः इन बॉड दरों में से एक उपयोग करते हैं:

- **115200** (सबसे सामान्य, GRBL 1.1+)
- **9600** (पुराने GRBL संस्करण)
- **250000** (कम सामान्य, कुछ कस्टम फ़र्मवेयर)

Rayforge की डिवाइस सेटिंग्स में भिन्न बॉड दरें आज़माएँ. सबसे सामान्य **115200** है.

### कनेक्शन बार-बार टूटता है

**समस्या:** Rayforge सफलतापूर्वक कनेक्ट होता है लेकिन बार-बार डिस्कनेक्ट और पुनः कनेक्ट होता रहता
है.

**संभावित कारण:**

1. **अविश्वसनीय USB केबल** - ज्ञात-अच्छी केबल से बदलें (अधिमानतः छोटी, &lt;2m)
2. **USB शक्ति समस्याएँ** - भिन्न USB पोर्ट आज़माएँ, अधिमानतः हब के बजाय कंप्यूटर पर स्वयं
3. **EMI/हस्तक्षेप** - USB केबलों को मोटर तारों और उच्च-वोल्टेज पावर सप्लाई से दूर रखें
4. **फ़र्मवेयर समस्याएँ** - संभव हो तो अपना GRBL फ़र्मवेयर अपडेट करें
5. **USB पोर्ट टकराव** - Windows पर भिन्न USB पोर्ट आज़माएँ

**समस्या निवारण चरण:**

```bash
# On Linux, monitor system logs while connecting:
sudo dmesg -w
```

ऐसे संदेश खोजें:

- "USB disconnect" - भौतिक/केबल समस्या दर्शाता है
- "device descriptor read error" - प्रायः शक्ति या केबल समस्या

### कनेक्शन के बाद डिवाइस प्रतिक्रिया नहीं देता

**समस्या:** कनेक्शन स्थिति "Connected" दिखाती है लेकिन मशीन कमांडों का प्रतिक्रिया नहीं देती.

**निदान:**

1. जाँचें कि सही फ़र्मवेयर प्रकार चयनित है (GRQL बनाम अन्य)
2. सत्यापित करें कि मशीन चालू है (नियंत्रक और पावर सप्लाई)
3. जाँचें कि मशीन अलार्म अवस्था में तो नहीं (होमिंग या अलार्म साफ़ की आवश्यकता)

**समाधान:**

Console में एक मैन्युअल कमांड भेजने का प्रयास करें:

- `?` - स्थिति रिपोर्ट का अनुरोध करें
- `$X` - अलार्म साफ़ करें
- `$H` - मशीन होम करें

यदि कोई प्रतिक्रिया नहीं, तो बॉड दर और पोर्ट चयन दोबारा जाँचें.

## कनेक्शन स्थिति संदेश

Rayforge भिन्न कनेक्शन अवस्थाएँ दिखाता है:

| स्थिति           | अर्थ                                         | क्रिया                                             |
| ---------------- | -------------------------------------------- | -------------------------------------------------- |
| **Disconnected** | किसी डिवाइस से कनेक्ट नहीं                   | पोर्ट कॉन्फ़िगर करके कनेक्ट करें                   |
| **Connecting**   | कनेक्शन स्थापित करने का प्रयास               | प्रतीक्षा करें, या अटक जाने पर कॉन्फ़िगरेशन जाँचें |
| **Connected**    | सफलतापूर्वक कनेक्ट, स्थिति प्राप्त कर रहा है | उपयोग के लिए तैयार                                 |
| **Error**        | कनेक्शन त्रुटि के साथ विफल                   | विवरण के लिए त्रुटि संदेश जाँचें                   |
| **Sleeping**     | पुनः कनेक्ट प्रयास से पहले प्रतीक्षा         | पिछला कनेक्शन विफल, 5s में पुनः प्रयास             |

## अपना कनेक्शन परीक्षण करें

### चरण-दर-चरण कनेक्शन परीक्षण

1. **मशीन कॉन्फ़िगर करें:**
   - Settings Machine खोलें
   - मशीन प्रोफ़ाइल चुनें या बनाएँ
   - सही ड्राइवर चुनें (GRBL Serial)
   - सीरियल पोर्ट चुनें
   - बॉड दर सेट करें (प्रायः 115200)

2. **कनेक्शन का प्रयास करें:**
   - मशीन नियंत्रण पैनल में "Connect" पर क्लिक करें
   - कनेक्शन स्थिति सूचक देखें

3. **संचार सत्यापित करें:**
   - कनेक्ट होने पर, स्थिति पूछताछ भेजने का प्रयास करें
   - मशीन अपनी स्थिति और अवस्था रिपोर्ट करनी चाहिए

4. **बुनियादी कमांड परीक्षण करें:**
   - यदि आपकी मशीन में लिमिट स्विच हैं तो होमिंग ($H) आज़माएँ
   - या आवश्यकता होने पर अलार्म साफ़ करें ($X)

### डिबग लॉग उपयोग करना

Rayforge कनेक्शन समस्याओं के लिए विस्तृत लॉगिंग शामिल करता है. डिबग लॉगिंग सक्षम करने के लिए:

```bash
# Run Rayforge from terminal with debug logging
rayforge --loglevel DEBUG
```

लॉग में यह जाँचें:

- कनेक्शन प्रयास और विफलताएँ
- प्रेषित (TX) और प्राप्त (RX) सीरियल डेटा
- स्टैक ट्रेसों के साथ त्रुटि संदेश

## उन्नत समस्या निवारण

### पोर्ट उपलब्धता मैन्युअल रूप से जाँचें

**Linux:**

```bash
# List all USB serial devices
ls -l /dev/ttyUSB* /dev/ttyACM*

# Check permissions
ls -l /dev/ttyUSB0  # Replace with your port

# Should show: crw-rw---- 1 root dialout
# You need to be in the 'dialout' group

# Test port manually
sudo minicom -D /dev/ttyUSB0 -b 115200
```

**Windows:**

```powershell
# List COM ports in PowerShell
[System.IO.Ports.SerialPort]::getportnames()

# Or use Device Manager:
# Win + X → Device Manager → Ports (COM & LPT)
```

### फ़र्मवेयर संगतता

Rayforge GRBL-संगत फ़र्मवेयर के लिए डिज़ाइन किया गया है. सुनिश्चित करें कि आपका नियंत्रक चलाता है:

- **GRBL 1.1** (सबसे सामान्य, अनुशंसित)
- **GRBL 0.9** (पुराना, सीमित सुविधाएँ हो सकती हैं)
- **grblHAL** (आधुनिक GRBL फ़ोर्क, समर्थित)

अन्य फ़र्मवेयर प्रकार (Marlin, Smoothieware) वर्तमान में GRBL ड्राइवर के माध्यम से समर्थित नहीं हैं.

### USB-टू-सीरियल चिपसेट

सामान्य चिपसेट और उनके ड्राइवर:

| चिपसेट              | Linux                     | Windows                                         | macOS         |
| ------------------- | ------------------------- | ----------------------------------------------- | ------------- |
| **CH340/CH341**     | अंतर्निहित कर्नेल ड्राइवर | [CH341SER driver](http://www.wch.cn/downloads/) | ड्राइवर चाहिए |
| **FTDI FT232**      | अंतर्निहित कर्नेल ड्राइवर | अंतर्निहित (Windows 10+)                        | अंतर्निहित    |
| **CP2102 (SiLabs)** | अंतर्निहित कर्नेल ड्राइवर | अंतर्निहित (Windows 10+)                        | अंतर्निहित    |

## अभी भी समस्या है?

यदि आपने ऊपर सब कुछ आज़मा लिया है और अभी भी कनेक्ट नहीं हो पा रहे:

1. **GitHub समस्याएँ जाँचें** - किसी ने वही समस्या रिपोर्ट की हो सकती है
2. निम्नलिखित के साथ एक **विस्तृत समस्या रिपोर्ट बनाएँ**:
   - ऑपरेटिंग सिस्टम और संस्करण
   - Rayforge संस्करण (Snap/Flatpak/AppImage/स्रोत)
   - नियंत्रक बोर्ड मॉडल और फ़र्मवेयर संस्करण
   - USB चिपसेट (Windows पर Device Manager या Linux पर `lsusb` जाँचें)
   - पूर्ण त्रुटि संदेश और डिबग लॉग
3. **किसी अन्य एप्लिकेशन से परीक्षण करें** - हार्डवेयर काम करता है सत्यापित करने के लिए सीरियल
   टर्मिनल (minicom, PuTTY, Arduino Serial Monitor) से कनेक्ट करने की कोशिश करें
